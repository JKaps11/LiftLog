# Whether a Set is timed or unilateral is read from the live Exercise, not from the Set

`.scratch/timed-exercises/spec.md` decided that "presence of `durationSeconds` on a given Set (not the Exercise's current `isTimed` value) is what drives rendering, forever, once that Set is logged", citing ADR-0001, and `SessionExerciseCard` accordingly chose its layout by sniffing `set.durationSeconds !== undefined`. **We are reversing that.** A Set now renders as timed or weighted according to the Exercise's current `isTimed`, and a Session's Sets materialize as solo Sets or left/right pairs according to its current `isUnilateral`, both looked up live by `exerciseId`.

The immediate forcing reason is ADR-0004: a Pending Set carries no measurements at all, so field presence can no longer distinguish a pending plank from a pending bench press. The deeper reason is that the sniffing was the odd one out to begin with. `isTimed` and `isUnilateral` are properties of the movement, declared once on the Exercise, and `logSet` already consulted `isUnilateral` live to decide pairing while `resolveExerciseDisplayName` already resolved names live with a fallback only for deleted Exercises. Duplicating the fact into each Set's field shape made the Set the second source of truth for something the Exercise owns.

`side` stays stored on the Set, and is not an inconsistency: which half of a pair a Set is cannot be derived from `isUnilateral`. Timed-ness can. The earlier decision lumped the two together as "shape" and that conflation is what it got wrong.

ADR-0001 was over-applied here. It exists so that stored performance is not rewritten or erased by later edits, and nothing about this reverses that — the logged numbers are untouched, only the frame they are displayed in changes. The behaviour this gives up is timed-exercises' user story 7 ("an Exercise's timed flag should only affect Sets logged after I set it"), and the trade is worth it: flipping `isTimed` is not a routine edit, since a plank is timed and a bench press is not. The realistic reason to flip it is that the Exercise was entered wrong, in which case re-rendering past Sets under the corrected truth is what the user wants, not a permanent record of the mistake.

The cost is that a mis-flip does misrepresent history: mark a genuinely timed Exercise as weighted and its logged seconds stop displaying, since the weighted layout reads `weight` and `reps`, which are absent. The data is not lost and flipping back restores the display.

When the Exercise has been deleted there is nothing to look up, so rendering falls back to inferring the layout from the Set's own measurement fields — the same live-lookup-with-fallback pattern `resolveExerciseDisplayName` uses. This works for every Logged Set in history; a Pending Set of a deleted Exercise falls through to weighted, reachable only by deleting an Exercise while a Session on it is open.
