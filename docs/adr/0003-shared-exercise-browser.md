# One exercise-browsing component, two row renderers; picking is a full-screen step

Exercises are browsed on two surfaces — the Exercises tab (manage: rename, delete) and the Workout builder's picker (select) — which were built as two separate implementations of the same idea and promptly drifted: the Exercises tab gained a Type segmented control, a jump-to-muscle-group rail, a sticky header and per-row badges, and the picker silently kept none of them. We decided both surfaces render through a single `ExerciseBrowser` that owns search, type filter, sticky header, jump rail, grouping and empty states, parameterized only by a `renderRow` callback for what a row contains. Anything added to browsing now reaches both surfaces by construction; there is no second copy to fall behind.

We also decided picking is a full-screen step rather than an inline section of the Workout form. The picker previously lived in a `max-h-64` scroll box inside the form, which on a phone with the keyboard raised shows about two exercise rows. Just as decisively: sticky positioning and the jump rail's `window.scrollY` arithmetic are written against page scroll, so reusing them inside a nested 16rem overflow container would mean reworking exactly the code we were trying to share.

Considered a single component with a `mode: 'manage' | 'select'` prop — rejected because it would pull rename/delete/inline-edit logic *and* selection logic inside the shared component, making every future difference between the two surfaces another internal branch. Considered exporting a `useExerciseBrowse()` hook plus a header component and letting each page compose its own layout — rejected because the list layout, section headers, group anchor ids and empty states would stay duplicated, and those are precisely the things that drifted.

The picker is a view swap inside `WorkoutForm` rather than a route or a dialog: the component stays mounted, so the in-progress Workout draft survives with no state hoisting. Because the app has no router, Android's back button would otherwise close the entire PWA from the picker, so the picker — and only the picker — pushes a history entry and treats popping it as Done. App-wide history integration for tabs and forms remains unaddressed.

Consequence worth naming: the picker's search input is now outside any `<form>`. That is load-bearing, not incidental. The original inline picker's search box sat inside the form holding the Save button, so Android's "Go" key fired implicit form submission and saved-and-exited the Workout mid-build. `WorkoutForm` additionally suppresses Enter-to-submit on its name field, so a Workout is saved only by a deliberate Save tap.
